## Verified in the executable

- Build 8606 has a native BLP2 parser. `0x005B1BA0` copies a 0x494-byte header-sized structure, compares its first word with `0x32504C42` (`BLP2`), and requires content type/version `1`.
- Code at `0x00453FF0`, `0x004544A0`, `0x00455EF0`, and `0x004561F0` constructs BLP2 descriptors and calls the parser. These are instructions, not incidental strings.
- The image contains renderer format names `GxTex_Dxt1`, `GxTex_Dxt3`, and `GxTex_Dxt5` and format-selection logic close to the BLP routines.
- The normal addon `Texture:SetTexture()` route therefore remains the first test path. TBCExtensions does not intercept it in this revision.

## LIKELY, but not yet fully proved

- Encoding 1 (paletted) and encoding 2 (DXT) are accepted by the stock path. The nearby branches distinguish alpha encodings including 0, 1, and 7, matching the familiar DXT1/DXT3/DXT5 mapping. Exact argument and object meanings still need named call-chain analysis.
