### Decision sequence

1. Independent BLP parser/decoder and synthetic controls were developed (`Graphics/Textures/BLPInspector.cpp`, `BLP2Decoder.cpp`, `BLP2Research/`, `Docs/TBC_BLP2_IMPLEMENTATION.md`). Owner tests established Palette and DXT1/3/5 stock rendering. Original encoding-3 BGRA8 parsed independently but showed a clean stock-path failure, no crash.
2. Offline-only BGRA8→DXT5 converter (`Tools/TextureResearch/bgra_to_dxt5.cpp`) generated a *separate* valid DXT5 file; reparse and owner visual quadrant PASS. This proves transformed bytes are stock-compatible, **not** runtime byte replacement. The original on disk remains encoding 3.
3. Static investigation found native BLP parser `0x005B1BA0`, retained raw pointer +0x498, a `0x005B3170` route with reusable global buffer at `0x00D43118/+0x20`, and source mip uses after parsing (`Docs/TBC_BLP2_RUNTIME_TRANSFORM.md`). A temporary vector pointer would be unsafe.
4. 0.1.6 one-shot detour at `0x005B3170` reported controlled BGRA8 **NO HIT**. The initial apparent blank Palette/DXT/offline controls were later explained by an open/locked patch/archive; after closure and restart the controls worked. That suspected format/Toolkit regression is **DEPRECATED / SUPERSEDED — TEST ENVIRONMENT ERROR**.
5. Static downward RE anchored Texture method table `0x009110B0`→`0x00434BE0`, setter `0x0042F920`, request `0x00457FC0`, possible loader `0x004576E0`, source caller `0x00455EF0`, parser `0x005B1BA0`. This is a plausible alternative to `0x005B3170`, not runtime-proven throughout.
6. 0.1.7 research-only detours at `0x00457FC0`, `0x00455EF0`, `0x005B1BA0` compare known DXT5 and BGRA8 by one-shot thread-local generation. The initial test established one matched, non-null request at `0x00457FC0` for each asset, but no deep correlation. The later owner-tested resource-identity revision reported BGRA8 generation 1: request total 26245, armed/matched 1/1, thread 30304, pointer `0x27E8AC08`; source/parser totals 1390/1492, armed/correlated 0/0, pointer-equal candidate 0. The original BGRA8 is no longer classified as simply blank or clean-failing.

`NativeBLPCorrelation.cpp` stores the actual returned `void*` in `g_req.object` but its Toolkit `return 1` is computed as `result != nullptr`, **not** the raw pointer or proof of a decoded texture.
